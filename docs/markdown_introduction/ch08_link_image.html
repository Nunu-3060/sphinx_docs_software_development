8. リンクと画像

この章では、Web ページや他のファイルへのリンクと、画像を表示する方法を説明する。リンクの書き方は何種類かあるが、よく使うのは最初に説明するインラインリンクである。

8.1. インラインリンク

リンクとして表示する文字を [ と ] で囲み、その直後にリンク先の URL を ( と ) で囲んで書く。これをインラインリンクと呼ぶ。HTML では <a> に変換される。

書き方

1詳しくは [CommonMark の公式サイト](https://commonmark.org/) を参照すること。

表示結果（CommonMark）

詳しくは CommonMark の公式サイト を参照すること。

] と ( の間に空白を入れてはいけない。空白があると、リンクにならずに文字のまま表示される。

URL の後に半角空白を入れ、" で囲んだ文字を書くと、リンクのタイトルになる。タイトルは、多くのブラウザでリンクにマウスポインターを重ねたときに表示される。

書き方

1[CommonMark](https://commonmark.org/ "CommonMark の公式サイト")

表示結果（CommonMark）

CommonMark

8.2. 参照リンク

URL が長いと、インラインリンクでは文章が読みにくくなる。そのようなときは、文中にはリンクの文字と参照名だけを書き、URL は文書の別の場所にまとめて書ける。これを参照リンクと呼ぶ。

書き方

1[CommonMark の仕様][cm-spec] と [GFM の仕様][gfm-spec] を読み比べる。
2
3[cm-spec]: https://spec.commonmark.org/
4[gfm-spec]: https://github.github.com/gfm/ "GitHub Flavored Markdown Spec"

表示結果（CommonMark）

CommonMark の仕様 と GFM の仕様 を読み比べる。

3 行目と 4 行目のように、行頭に [参照名]: を書き、その後に URL を書いてリンク先を定義する。定義の行そのものは表示されない。定義は文書のどこに書いてもよいが、段落の直後の行に空行を入れずに書くと、段落の一部として扱われて文字のまま表示される。定義の前には空行を入れ、参照している段落の後や文書の末尾にまとめると読みやすい。参照名では大文字と小文字は区別されない。

リンクの文字と参照名が同じなら、参照名を省略して [CommonMark][] または [CommonMark] とだけ書くこともできる。

8.3. 自動リンク

URL を < と > で囲むと、URL そのものがリンクとして表示される。これを自動リンクと呼ぶ。

書き方

1公式サイト：<https://commonmark.org/>

表示結果（CommonMark）

公式サイト：https://commonmark.org/

GFM では、< と > で囲まなくても、https:// や www. で始まる文字列が自動でリンクになる。これを拡張自動リンクと呼ぶ。

書き方

1公式サイト：https://commonmark.org/
2
3www.example.com も自動でリンクになる。

表示結果（GitHub）

公式サイト：https://commonmark.org/

www.example.com も自動でリンクになる。

拡張自動リンクは便利だが、CommonMark だけに対応した場所ではリンクにならない。また、日本語の文章の中に URL を直接書くと、URL の直後の文字までリンクに含まれてしまうことがある。URL の前後には半角空白を入れるか、< と > で囲むと確実である。

8.4. リポジトリ内のファイルへのリンク

リンク先には、URL だけでなく、ファイルの相対パスも書ける。GitHub のリポジトリの中の文書から、同じリポジトリの別のファイルへリンクするときに使う。

書き方

1- インストール方法は [INSTALL.md](INSTALL.md) を参照すること。
2- 設定の説明は [docs/config.md](docs/config.md) にある。
3- 1 つ上のフォルダの文書：[README](../README.md)

相対パスは、リンクを書いた文書のある場所を基準にする。../ は 1 つ上のフォルダを表す。GitHub では、リンクをクリックすると、リポジトリの中の該当するファイルが表示される。相対パスで書いておけば、リポジトリの名前やブランチが変わってもリンクが切れない。本書にはリンク先のファイルがないため、この例の表示結果は省略した。

8.5. 見出しへのリンク

GitHub などでは、文書の見出しにアンカー（リンク先として指定するための名前）が自動で付けられる。リンク先に # とアンカーを書くと、その見出しへのリンクになる。

書き方

 1## 目次
 2
 3- [インストール方法](#インストール方法)
 4- [使い方](#使い方)
 5
 6## インストール方法
 7
 8次のコマンドを実行する。
 9
10## 使い方
11
12[目次に戻る](#目次)

表示結果（GitHub）

目次

  • インストール方法
  • 使い方

インストール方法

使い方

目次に戻る

表示結果のリンクをクリックすると、表示結果の中の該当する見出しへ移動する。GitHub が見出しからアンカーを作る規則はおおむね次のとおりである。

  • 英字は小文字にする。

  • 半角空白はハイフン（-）にする。

  • ハイフンとアンダースコア以外の記号（.、!、? など）は取り除く。

  • 日本語の文字はそのまま残す。

  • 同じ文字の見出しが複数あるときは、2 つ目以降の末尾に -1、-2 を付ける。

たとえば、## Getting Started! という見出しのアンカーは getting-started になり、## 第 1 章 概要 のアンカーは 第-1-章-概要 になる。正確なアンカーが分からないときは、GitHub で見出しにマウスポインターを重ねると表示されるリンクの記号から確かめられる。

別のファイルの見出しへリンクするときは、[設定項目](docs/config.md#設定項目) のように、相対パスの後に # とアンカーを続ける。

なお、アンカーの作り方は場所によって異なる。日本語の見出しのアンカーの扱いは特に違いが大きいので、GitHub 以外の場所では表示して確かめる必要がある。

8.6. 画像

リンクの書き方の先頭に ! を付けると、画像になる。[ と ] の中には、画像の代わりに表示する文章である代替テキストを書く。HTML では <img> に変換される。

書き方

1![サンプル画像：青い円と緑の三角形](images/sample.png)

表示結果（CommonMark）

代替テキストは、画像を読み込めなかったときや、目の不自由な人が画面を音声で読み上げるソフトウェアを使うときに、画像の代わりに使われる。「画像」のような意味のない言葉ではなく、画像が伝えたい内容を短く書く。

リンクと同じく、URL の後に " で囲んでタイトルを付けることもできる。また、画像をリンクの文字の位置に書くと、クリックできる画像になる。

書き方

1[![サンプル画像](images/sample.png "クリックすると画像だけを表示する")](images/sample.png)

表示結果（CommonMark）

Markdown には画像の大きさを指定する記法がない。大きさを指定したいときは、HTML の <img> タグを直接書く（第 10 章で説明する）。
