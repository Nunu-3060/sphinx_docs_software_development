7. 引用・コードブロック・区切り線

この章では、他の文章を引用する書き方、複数行のコードを示すコードブロック、区切り線を説明する。いずれも段落とは別のブロック要素として表示される。

7.1. 引用

行頭に > と半角空白を書くと、その行は引用になる。HTML では <blockquote> に変換される。電子メールの返信で、元の文章の行頭に > を付けて引用する習慣から取られた記法である。

書き方

1公式ドキュメントには次のように書かれている。
2
3> 仮想環境を作成した後は、
4> 必要なパッケージをインストールすること。

表示結果（CommonMark）

公式ドキュメントには次のように書かれている。

仮想環境を作成した後は、 必要なパッケージをインストールすること。

引用の中は、段落と同じく 1 回の改行では改行されない。引用の中で段落を分けたいときは、> だけの行を空行の代わりに入れる。引用の中では、見出しやリストなど他の記法も使える。

書き方

1> ## 注意事項
2>
3> 次の 2 点を守ること。
4>
5> - 作業前に最新のコードを取得する
6> - 作業後にテストを実行する

表示結果（CommonMark）

注意事項

次の 2 点を守ること。

  • 作業前に最新のコードを取得する
  • 作業後にテストを実行する

> を重ねると、引用を入れ子にできる。

書き方

1> 明日の会議は 10 時からでよいか。
2>
3> > 10 時からで問題ない。

表示結果（CommonMark）

明日の会議は 10 時からでよいか。

10 時からで問題ない。

CommonMark では、引用の中の段落が続いている間は、2 行目以降の > を省略しても引用の続きとして扱われる。しかし、ソースが読みにくくなり、意図せず引用が続いてしまう原因にもなるので、引用するすべての行に > を付ける。また、引用の後に普通の段落を続けるときは、間に空行を入れる。

書き方

1> 引用した文章。
2ここも引用の続きになる。
3
4ここは引用の外になる。

表示結果（CommonMark）

引用した文章。 ここも引用の続きになる。

ここは引用の外になる。

7.2. コードブロック

複数行のコードやコマンドの実行結果を示すときは、コードブロックを使う。コードブロックの中は、インラインコードと同じく Markdown の記法が解釈されず、等幅のフォントで書いたとおりに表示される。HTML では <pre> と <code> に変換される。

7.2.1. フェンスで囲むコードブロック

バッククォートを 3 個並べた行で、コードの前後を囲む。この囲みの行をフェンスと呼ぶ。

書き方

 1```
 2def greet(name):
 3    print(f"Hello, {name}!")
 4```
 5
 6Markdown の記号もそのまま表示される。
 7
 8```
 9# 見出しにならない
10- 箇条書きにならない
11```

表示結果（CommonMark）

def greet(name):
    print(f"Hello, {name}!")

Markdown の記号もそのまま表示される。

# 見出しにならない
- 箇条書きにならない

バッククォートの代わりにチルダ（~）を 3 個並べてもよい。開始と終了のフェンスには同じ種類の記号を使い、終了のフェンスは開始のフェンス以上の個数にする。

開始のフェンスの直後に言語名を書くと、多くの場所でコードが言語の文法に合わせて色分けされる。これをシンタックスハイライトと呼ぶ。

書き方

1```python
2def greet(name):
3    print(f"Hello, {name}!")
4```

表示結果（CommonMark）

def greet(name):
    print(f"Hello, {name}!")

言語名には、python、javascript、bash、json、html、diff などを書く。使える言語名は表示する場所（GitHub など）によって決まる。色分けが不要な文章やエラーメッセージには text と書くと、意図が明確になる。本書の表示結果には色分けの機能がないため、言語名を書いても色は付かないが、GitHub や VS Code のプレビューでは色が付く。

コードブロックの中に ``` を含む文章（Markdown のソースなど）を示したいときは、外側のフェンスのバッククォートを 4 個以上にする。中の ``` は、外側より短いのでフェンスとはみなされない。

書き方

1````markdown
2コードブロックは次のように書く。
3
4```python
5print("Hello")
6```
7````

表示結果（CommonMark）

コードブロックは次のように書く。

```python
print("Hello")
```

7.2.2. インデントによるコードブロック

空行の後で、行頭に半角空白を 4 個以上入れた行も、コードブロックになる。段落の直後の行の場合は、コードブロックにならずに段落の続きとして扱われる。これは元の Markdown からある書き方である。

書き方

1次のコマンドを実行する。
2
3    python main.py

表示結果（CommonMark）

次のコマンドを実行する。

python main.py

インデントによるコードブロックは、言語名を指定できないうえに、リストの中で使うと字下げの量が分かりにくくなる。たとえば、リストの項目の中にコードブロックを入れるには、項目の本文の開始位置から、さらに 4 文字字下げする必要がある。逆に、リストの続きのつもりで深く字下げした文章が、意図せずコードブロックになることもある。

書き方

1- 項目の本文
2
3      項目の本文から 4 文字字下げしたので、コードブロックになる
4
5普通の段落のつもりで 4 文字字下げした行もコードブロックになる。
6
7    字下げした行

表示結果（CommonMark）

  • 項目の本文

    項目の本文から 4 文字字下げしたので、コードブロックになる

普通の段落のつもりで 4 文字字下げした行もコードブロックになる。

字下げした行

コードブロックには、フェンスで囲む書き方を使うほうがよい。また、空行の後の文章の行頭に、不用意に 4 個以上の空白を入れないように注意する。

7.3. 区切り線

-、*、_ のいずれかを 3 個以上並べた行は、区切り線（水平線）になる。HTML では <hr> に変換される。記号の間に空白を入れてもよい。

書き方

1前半の話題。
2
3---
4
5後半の話題。
6
7***
8
9* * *

表示結果（CommonMark）

前半の話題。

後半の話題。

- を並べる書き方には注意が必要である。段落の直後の行に --- を書くと、区切り線ではなく、その段落を見出しにする Setext 形式の見出し（第 4 章）として扱われる。

書き方

1区切り線のつもり
2---
3
4区切り線になる
5
6---

表示結果（CommonMark）

区切り線のつもり

区切り線になる

区切り線の前後には必ず空行を入れる。--- で迷う場合は、Setext 形式と紛らわしくない *** を使ってもよい。
