10. HTML の埋め込みと GitHub の独自機能

この章では、Markdown の中に HTML を直接書く方法と、GitHub が独自に対応している機能（脚注、数式、アラート、Mermaid による図、絵文字）を説明する。どちらも、表示する場所によって使えるかどうかが異なる点に注意が必要である。

10.1. HTML を直接書く

CommonMark では、Markdown の中に HTML のタグを直接書ける。Markdown の記法では表せない表示をしたいときに使う。

10.1.1. 改行

<br> を書くと、その位置で改行される。表のセルの中など、強制改行（第 4 章）が使えない場所で役に立つ。

書き方

1| 項目 | 内容 |
2| --- | --- |
3| 住所 | 東京都千代田区<br>1-1-1 |

表示結果（GitHub）

項目 内容
住所 東京都千代田区
1-1-1

10.1.2. 画像の大きさ

Markdown の画像の記法では大きさを指定できない。<img> タグを直接書けば、width 属性で幅を指定できる。

書き方

1<img src="images/sample.png" alt="サンプル画像" width="120">

表示結果（CommonMark）

10.1.3. 折りたたみ

<details> と <summary> を使うと、クリックすると開く折りたたみの部分を作れる。長いログや補足の説明を、普段は隠しておきたいときに使う。

書き方

 1<details>
 2<summary>エラーの詳細（クリックで開く）</summary>
 3
 4```text
 5Traceback (most recent call last):
 6  File "main.py", line 1, in <module>
 7    import requests
 8ModuleNotFoundError: No module named 'requests'
 9```
10
11</details>

表示結果（CommonMark）

エラーの詳細（クリックで開く） 
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    import requests
ModuleNotFoundError: No module named 'requests'

<summary> の行の後と </details> の行の前に空行を入れると、その間に Markdown の記法（この例ではコードブロック）を書ける。空行がないと、間の文章は HTML の一部として扱われ、Markdown の記法が解釈されない。

10.1.4. コメント

<!-- と --> で囲んだ部分は HTML のコメントになり、表示されない。書きかけのメモや、文書を編集する人への注意を残したいときに使う。

書き方

1この段落は表示される。
2
3<!-- TODO: 次回の更新で手順を追加する -->
4
5この段落も表示される。

表示結果（CommonMark）

この段落は表示される。

この段落も表示される。

ただし、コメントは表示されないだけで、ソースを開けば誰でも読める。公開したくない情報を書いてはいけない。

10.1.5. HTML が取り除かれる場所

HTML を書けると、悪意のあるプログラム（<script> タグなど）を埋め込まれる危険がある。そのため、多くのサービスでは、安全のために一部のタグや属性を取り除いてから表示する。GitHub でも、<script> や <style> などのタグや、style 属性などは取り除かれる。どのタグを使えるかはサービスによって異なり、HTML をまったく使えない場所もある。

HTML は Markdown の記法では表せないときに限って使い、使った場合は実際に表示される場所で確かめるようにする。

10.2. GitHub の独自機能

ここからは、GFM の仕様にはないが、GitHub が独自に対応している機能を説明する。他のサービスでも似た機能を持つことが多いが、書き方が異なったり、対応していなかったりする。

10.2.1. 脚注

文中に [^ラベル] と書くと、脚注への参照になる。脚注の内容は、別の行に [^ラベル]: と書いて定義する。脚注は文書の末尾にまとめて表示され、参照の位置には番号が表示される。

書き方

1Markdown は 2004 年に公開された[^1]。CommonMark は Markdown の仕様である[^cm]。
2
3[^1]: John Gruber による。
4[^cm]: 2014 年に作られた。

表示結果（GitHub）

Markdown は 2004 年に公開された[1]。CommonMark は Markdown の仕様である[2]。

  1. John Gruber による。 ↩︎

  2. 2014 年に作られた。 ↩︎

ラベルには数字だけでなく単語も使える。表示される番号は、ラベルにかかわらず、文中で参照した順に 1 から振られる。脚注の定義は文書のどこに書いてもよい。

10.2.2. 数式

$ で囲むと文中の数式、$$ だけの行で囲むと独立した行の数式になる。数式は、数学の論文などで使われる LaTeX という書き方で書く。

書き方

1円の面積は $S = \pi r^2$ で求められる。
2
3$$
4x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
5$$

表示結果（GitHub）

円の面積は \(S = \pi r^2\) で求められる。

\[x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}\]

LaTeX の書き方は本書の範囲を超えるので説明しない。\pi が円周率の記号、\frac{分子}{分母} が分数、\sqrt{...} が平方根を表す、という程度を知っておけば、簡単な数式は読める。

文章の中で金額を表す $ を使うと、数式として解釈されてしまうことがある。その場合は \$ とエスケープする。

10.2.3. アラート

引用の 1 行目に [!NOTE] などと書くと、色の付いた注意書き（アラート）になる。種類は次の 5 つである。

表 10.1 アラートの種類

書き方

用途

[!NOTE]

補足。読み飛ばしてもよいが知っておくと役に立つ情報

[!TIP]

ヒント。作業をうまく進めるための助言

[!IMPORTANT]

重要。目的を達成するために必要な情報

[!WARNING]

警告。問題を避けるために、すぐに注意すべき情報

[!CAUTION]

注意。行動した結果として起こりうる危険

書き方

1> [!NOTE]
2> 設定ファイルは初回の起動時に自動で作られる。
3
4> [!WARNING]
5> この操作は取り消せない。

表示結果（GitHub）

Note

設定ファイルは初回の起動時に自動で作られる。

Warning

この操作は取り消せない。

アラートの見出し（Note、Warning など）は英語で表示される。本書の表示結果は GitHub の色に近づけているが、GitHub では見出しの前にアイコンも表示される。アラートを多用すると、かえって重要な情報が目立たなくなるので、本当に必要な箇所に限って使う。

10.2.4. Mermaid による図

コードブロックの言語名に mermaid と書くと、その中に書いた Mermaid という記法の文章から図が描かれる。Mermaid では、流れ図、シーケンス図、ガントチャートなどを文章で書ける。

書き方

1```mermaid
2flowchart TD
3    A[開始] --> B{入力は正しいか}
4    B -- はい --> C[保存する]
5    B -- いいえ --> D[エラーを表示する]
6    C --> E[終了]
7    D --> E
8```

本書の変換プログラムは Mermaid に対応していないため、表示結果は出せない。GitHub では、このソースから次の図のような流れ図が描かれる。次の図は同じ内容を Graphviz という別のツールで描いたもので、色や形などの見た目は GitHub の表示とは異なる。

図を画像ファイルとして用意する代わりに文章で書いておけば、図を修正するときにソースを書き換えるだけで済み、変更の履歴も Git で追える。Mermaid の詳しい書き方は、Mermaid の公式サイト（付録 C）を参照すること。

10.2.5. 絵文字

: で英単語を挟むと、対応する絵文字に置き換えられる。たとえば :smile: は笑顔の絵文字に、:+1: は親指を立てた絵文字に、:warning: は警告の絵文字になる。

書き方

1レビューありがとう :+1:

本書の変換プログラムはこの機能に対応していないため、表示結果は出せない。絵文字そのものを Unicode の文字として直接入力してもよい。
