1. Markdown とは

この章では、Markdown がどのような言語で、なぜ広く使われているのかを説明する。また、Markdown には「方言」と呼ばれる複数の種類があることと、本書での記法の分け方を説明する。

1.1. 軽量マークアップ言語

文書の中の「ここは見出し」「ここは箇条書き」といった構造や書式を、決められた記号で書き表すことをマークアップと呼ぶ。Web ページの記述に使う HTML は代表的なマークアップ言語で、見出しは <h1> と </h1> のようなタグで囲んで書く。

HTML はできることが多い反面、タグの記述が多く、ソースのままでは読みにくい。これに対して、少ない記号で手軽に書けるように作られたマークアップ言語を軽量マークアップ言語と呼ぶ。Markdown はその代表である。

同じ内容を HTML と Markdown で書き比べてみる。まず HTML で書くと次のようになる。

リスト 1.1 HTML で書いた文書
1<h1>買い物メモ</h1>
2<p>今週末に買うものを書き出す。</p>
3<ul>
4  <li>牛乳</li>
5  <li><strong>卵</strong>（必ず買う）</li>
6  <li>パン</li>
7</ul>

同じ内容を Markdown で書くと次のようになる。本書では、このように Markdown のソースを「書き方」として示し、その下に変換した結果を「表示結果」として示す。

書き方

1# 買い物メモ
2
3今週末に買うものを書き出す。
4
5- 牛乳
6- **卵**（必ず買う）
7- パン

表示結果（CommonMark）

買い物メモ

今週末に買うものを書き出す。

  • 牛乳
  • 卵（必ず買う）
  • パン

Markdown のソースには < や > で囲まれたタグがないので、変換する前の文字のままでも内容を読み取れる。行頭の # が見出し、行頭の - が箇条書き、** で囲んだ部分が強調を表す、という対応も直感的である。

Markdown のソースは、ブラウザなどで表示する前に HTML に変換される。この変換や、変換した結果を画面に表示することをレンダリングと呼ぶ。変換の流れは第 2 章で説明する。

1.2. Markdown の成り立ち

Markdown は、2004 年に John Gruber が Aaron Swartz の協力を得て公開した。公開されたのは、記法を説明する文書と、Markdown を HTML に変換する Perl のプログラム（Markdown.pl）である。

Gruber が掲げた設計方針は、「Markdown で書いた文書は、タグや書式の指示が埋め込まれているようには見えず、プレーンテキストのままでそのまま公開できるくらい読みやすくなければならない」というものである。記号の多くは、それ以前から電子メールなどのプレーンテキストで使われていた書き方（行頭に > を付けて引用を表す、行頭に - や * を付けて箇条書きにするなど）から取られている。

1.3. 方言と標準化

Gruber の文書は記法を例で説明したもので、細かい規則までは定めていなかった。たとえば「リストの中にリストを書くには何文字字下げすればよいか」「強調の記号が入れ子になったらどう解釈するか」といった点があいまいだった。そのため、Markdown を HTML に変換するプログラムが作られるたびに、細部の解釈が少しずつ異なるものが生まれた。また、表や取り消し線など、元の Markdown にない記法を独自に追加するものも現れた。このように、少しずつ異なる Markdown の変種を方言と呼ぶ。

方言の違いを解消するため、2014 年に有志によって CommonMark という仕様が作られた。CommonMark は、あいまいだった規則を細かく定め、多数のテスト例とともに公開している。現在では多くのサービスやツールが CommonMark を基礎にしている。

GitHub は、CommonMark に表やタスクリストなどの拡張を加えた GFM（GitHub Flavored Markdown）の仕様を公開している。さらに GitHub は、GFM の仕様にない機能（脚注、数式、アラートと呼ばれる注意書きの表示など）にも独自に対応している。他のサービスも、CommonMark や GFM を基礎にして、それぞれ独自の機能を加えていることが多い。

1.4. 本書での記法の分け方

本書では、記法を次の 3 つに分けて説明する。どこで使える記法なのかを意識できるようにするためである。

表 1.1 本書での記法の分類

分類

内容

主な記法

CommonMark

CommonMark の仕様で定められた基本の記法。CommonMark に準拠したほとんどの場所で使える

見出し、段落、強調、リスト、引用、コードブロック、リンク、画像

GFM

GFM の仕様で CommonMark に追加された記法。GitHub をはじめ、多くの場所で使える

脚注、数式、アラート、Mermaid による図、絵文字

1.5. 他の軽量マークアップ言語

軽量マークアップ言語は Markdown だけではない。代表的なものに、Python の文書作成で使われる reStructuredText と、書籍や技術文書の作成で使われる AsciiDoc がある。

表 1.2 主な軽量マークアップ言語

言語

特徴

主な用途

Markdown

記法が少なく覚えやすい。使える場所が非常に多い

README、Issue、ブログ、メモ

reStructuredText

記法が多く、相互参照や目次など長い文書のための機能が充実している

Python のドキュメント、Sphinx で作る文書

AsciiDoc

書籍の執筆に必要な機能（相互参照、表の結合など）を標準で備える

技術書、製品マニュアル

本書自体は reStructuredText で書き、Sphinx という文書作成ツールで HTML に変換している。記法の豊富さでは他の 2 つに劣るものの、手軽さと使える場所の多さから、日常的に書く文書では Markdown が最もよく使われている。

1.6. Markdown が使われる場所

Markdown は、エンジニアが文書を書くさまざまな場所で使われている。

表 1.3 Markdown が使われる主な場所

場所

使われ方

GitHub、GitLab

リポジトリの README、Issue、プルリクエスト、Wiki、コメント

Qiita、Zenn

技術記事の執筆

一度覚えれば、チャットツールを除くこれらの場所で、ほぼ同じ書き方が使える。これが Markdown を学ぶ最大の利点である。

1.7. 本書の読み方

第 2 章で Markdown を書く環境を用意し、第 3 章で短い文書を 1 つ書いてみる。第 4 章から第 10 章では記法を 1 つずつ説明する。第 11 章では README を書く実践を行い、第 12 章では表示する場所による違いと書き方の指針を、第 13 章では Markdown のその他の活用方法を紹介する。付録には、記法の早見表、用語集、参考文献をまとめた。

本書の表示結果は、Python で書かれた変換プログラムである markdown-it-py を使って作っている。表示結果の上には「表示結果（CommonMark）」または「表示結果（GitHub）」と示した。前者は CommonMark の記法だけで変換した結果、後者は GitHub に近い設定で変換した結果である。どちらも、表示の細部（文字の大きさや色、余白など）は実際のサービスとは異なることがある。
