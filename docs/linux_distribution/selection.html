6. 用途別の選定指針

本章では、ディストリビューションを選定する際の観点と、用途別の候補を示す。

6.1. 選定の観点

ディストリビューションを選定する際に確認すべき主な観点を表 6.1 に示す。

表 6.1 選定の観点

観点

確認すること

サポート期間

システムの想定稼働期間をサポート期間でカバーできるか。メジャーバージョンの更新がどの程度の頻度で必要になるか。

サポート体制

障害時の問い合わせ先が必要か。必要な場合、開発元または第三者による商用サポートを利用できるか。その費用はどの程度か。

動作認証

利用予定の商用ソフトウェアやハードウェアが、そのディストリビューションをサポート対象としているか。

パッケージの充実度

必要なソフトウェアが公式リポジトリで提供されているか。必要なバージョンが入手できるか。

情報量

公式ドキュメントやコミュニティの情報が充実しているか。

運用ノウハウ

組織内に経験者がいるか。既存の構成管理（Ansible など）や監視の仕組みを流用できるか。

実行環境

利用するクラウドで公式イメージが提供されているか。必要なアーキテクチャ（arm64 など）をサポートしているか。

更新の方針

新しいソフトウェアを優先するか、動作の安定を優先するか。

6.2. 用途別の候補

用途別の候補を表 6.2 に示す。ここに挙げたものは代表的な候補であり、実際の選定では前節の観点に沿って評価すること。

表 6.2 用途別の候補

用途

候補

理由

企業の基幹システム

RHEL、SLES

サポート期間が長く、商用ソフトウェアの動作認証と開発元のサポートが得られる。

費用を抑えた RHEL 互換のサーバ

Rocky Linux、AlmaLinux、Oracle Linux

RHEL と同等のサポート期間を無償で利用できる。必要に応じて第三者の商用サポートを契約できる。

一般的な Web サーバ・クラウド上のサーバ

Ubuntu LTS、Debian、Amazon Linux 2023（AWS の場合）

情報量が多く、主要なクラウドで公式イメージが提供されている。

コンテナのベースイメージ

Alpine Linux、Debian、Ubuntu、Red Hat Universal Base Image（UBI）

イメージの小ささを優先するなら Alpine Linux、glibc との互換性を優先するなら Debian や Ubuntu、RHEL 上での実行と Red Hat のサポートを重視するなら UBI が適する。

開発者のデスクトップ

Ubuntu、Fedora、Linux Mint、openSUSE Tumbleweed

新しいソフトウェアやハードウェアへの対応が早い。Linux Mint は Windows から移行する利用者にも使いやすい。

Linux の仕組みの学習

Arch Linux、Gentoo、Slackware

利用者が自分でシステムを組み上げるため、構成要素の役割を理解しやすい。

ネットワーク機器・組込み機器

Alpine Linux、Debian

フットプリントが小さい、または対応アーキテクチャが多い。本格的な組込み開発では、Yocto Project などのビルドシステムで独自のディストリビューションを構築することが多い。

UBI は、RHEL のパッケージを基に Red Hat 社が無償で配布するコンテナのベースイメージである。

6.3. サポート終了への備え

どのディストリビューションを選んでも、いずれはサポート期間が終了する。サポートが終了したディストリビューションにはセキュリティ修正が提供されないため、次の点に留意して計画的に更新・移行する必要がある。

  • 構築時点で、メジャーバージョンの更新または移行の時期を運用計画に組み込んでおく。

  • 構成管理ツールやコンテナを使い、環境を再構築しやすくしておく。特定のディストリビューションに依存する手順は少なくしておくと、移行の負担を減らせる。

  • CentOS Linux の例のように、サポート期間が途中で短縮されることもある。開発元の発表やサポート期限の変更を定期的に確認する。
