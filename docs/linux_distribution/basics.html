2. Linux ディストリビューションの基礎

本章では、ディストリビューションを比較する前提となる概念を説明する。

2.1. Linux カーネルとディストリビューション

厳密には、Linux は Linus Torvalds が開発を始めた OS カーネルの名称である。カーネルはプロセス管理、メモリ管理、デバイスドライバ、ファイルシステムなどを担うが、カーネル単体にはシェルもコンパイラも含まれず、利用者が直接使える OS にはならない。

ディストリビューションは、Linux カーネルに C ライブラリ、init システム、GNU のツール群、各種アプリケーションを組み合わせ、インストーラやパッケージ管理の仕組みとともに一つの OS として利用できる形にまとめたものである。同じ Linux カーネルを使っていても、どのソフトウェアをどのような方針で組み合わせ、どのように配布・保守するかはディストリビューションごとに異なる。

2.3. パッケージ管理

ディストリビューションの性格を最もよく表すのがパッケージ管理システムである。パッケージ管理システムは、ビルド済みのソフトウェアをパッケージとしてリポジトリから取得し、依存関係を解決しながら導入・更新・削除する。

パッケージ管理は、低水準ツールと高水準ツールの二層構造になっていることが多い。低水準ツールは個々のパッケージファイルの展開や登録を担い、高水準ツールはリポジトリからの取得と依存関係の解決を担う。

同じ RPM 形式であっても、パッケージ名、依存関係の表現、ファイル配置はディストリビューションごとに異なるため、Red Hat 系向けの RPM パッケージを SUSE 系でそのまま使えるとは限らない。

2.4. リリースモデル

ディストリビューションの更新の方式は、大きく固定リリースとローリングリリースに分けられる。

固定リリース

一定の時期にバージョンを確定させ、そのバージョンの中ではセキュリティ修正と不具合修正を中心に提供する方式である。収録するソフトウェアのメジャーバージョンが原則として変わらないため、動作を予測しやすい。バージョン内の修正をまとめた版をポイントリリース（マイナーリリース）と呼ぶ。Debian、Ubuntu、RHEL、SLES などがこの方式をとる。

ローリングリリース

バージョンの区切りを設けず、パッケージを継続的に最新版へ更新する方式である。常に新しいソフトウェアを使える一方、更新による挙動の変化を受けやすい。Arch Linux、Gentoo、openSUSE Tumbleweed などがこの方式をとる。

固定リリースのうち、特に長期間サポートされる版を LTS（Long Term Support）と呼ぶ。Ubuntu の LTS が代表例である。

2.5. アップストリームとダウンストリーム

ソフトウェアの開発元をアップストリーム、それを取り込んで配布する側をダウンストリームと呼ぶ。ディストリビューションは、収録する各ソフトウェアのダウンストリームにあたる。ディストリビューションで見つかった不具合の修正は、アップストリームに還元することが望ましいとされる。

ディストリビューション同士にも同様の関係がある。Ubuntu は Debian のパッケージを基にしているため、Debian は Ubuntu のアップストリームである。Red Hat 系では、Fedora、CentOS Stream、RHEL の順に変更が流れる。

また、商用ディストリビューションの公開ソースコードからバイナリを再構築し、互換性を持たせたディストリビューションをリビルドディストリビューションと呼ぶ。RHEL に対する Rocky Linux、AlmaLinux が代表例である。

2.6. コミュニティ版と商用版

ディストリビューションは、開発・保守の主体によってコミュニティ版と商用版に大別できる。コミュニティ版は、ボランティアや非営利の財団が中心となって開発・配布する。商用版は、企業が有償のサブスクリプションとともに提供する。

商用版の代表は RHEL と SLES である。サブスクリプション契約により、バイナリの更新、技術サポート、ハードウェアベンダやソフトウェアベンダ（ISV）による動作認証が提供される。Ubuntu は誰でも無償で利用でき、開発元の Canonical が延長サポートや技術サポートを Ubuntu Pro として有償で提供している。

コミュニティ版の品質が低いとは限らない。例えば Debian は 30 年以上の実績を持ち、多くのディストリビューションの基盤となっている。ただし、障害時の問い合わせ先や長期のサポートが契約上必要な場合は、商用版または第三者の有償サポートを検討することになる。
